## P0 — Critical (fix first)

### C1. `detect_script` corrupts all SLP1 input ✅ VERIFIED
**`sanskrit_analyzer/utils/normalize.py:44`** — BUG
The SLP1 heuristic `re.compile(r"[wWqQzSN]|[AIURLMH](?![a-z])")` requires an SLP1 marker *not* followed by a lowercase letter. The common case — marker followed by a lowercase letter — fails the match and falls through to IAST.

**Reproduced:**
```
detect_script('rAma')   -> Script.IAST   (should be SLP1)
detect_script('gacCati')-> Script.IAST   (should be SLP1)
detect_script('kf')     -> Script.IAST   (should be SLP1)
normalize_slp1('rAma')  -> 'rama'        # long ā silently dropped
```
**Blast radius:** all four engines normalize through this (`vidyut_engine.py:71`, `heritage_engine.py:64`, `dharmamitra_engine.py:91`, `local_byt5_engine.py:154`), so corrupted text reaches every analysis path.
**Fix:** detect SLP1 *before* IAST and broaden the marker set to any interior SLP1 letter; or require callers to pass an explicit `source_script` instead of guessing.

### C2. MCP server drops 8 of 12 tools ✅ VERIFIED
**`sanskrit_analyzer/mcp/server.py:55-61`** — BUG
`register_analysis_tools`, `register_dhatu_tools`, `register_grammar_tools` each call `@server.list_tools()` / `@server.call_tool()`. The MCP low-level `Server` stores **one handler per request type** (dict assignment, not append), so only the last registrar (grammar) survives.

**Reproduced** — `list_tools` returns only:
```
['explain_parse', 'identify_compound', 'get_pratyaya', 'resolve_ambiguity']
```
Missing (unreachable): `analyze_sentence`, `split_sandhi`, `get_morphology`, `transliterate`, `lookup_dhatu`, `search_dhatu`, `conjugate_verb`, `list_gana`. Same overwrite hits resources (dhatu `read_resource` lost to grammar's).
**Fix:** register a single combined `list_tools`/`call_tool`/`list_resources`/`read_resource` handler that aggregates all tools and dispatches by name/URI.

### C3. Training data generator writes empty output ✅ VERIFIED
**`sanskrit_analyzer/training/data_generator.py:90`** — BUG
```python
parse_dict = result.model_dump() if hasattr(result, "model_dump") else {}
```
The analyzer returns an `AnalysisTree` dataclass (`models/tree.py:190`) with `to_dict()` and **no** `model_dump`, so the branch is always False.

**Reproduced:** awaited `Analyzer.analyze('rama')` → `AnalysisTree`; `hasattr(r,'model_dump')` = False; buggy line yields `parse_dict = {}`. Downstream `process_analysis_result` reads `parse_result.get("parse_forest", [])` → `[]` → `generate-disambig` produces **0 examples**; every grammar example has `"output": {}`.
**Fix:** call `result.to_dict()`; add a `to_dict` fallback alongside the `model_dump` check.

## P1 — High

### H1. Dharmamitra live-API 422 breaks engine + fails 6 tests ✅ VERIFIED
**`sanskrit_analyzer/engines/dharmamitra_engine.py:158`** — BUG + test fragility
The engine POSTs `mode="unsandhied-lemma-morphosyntax"` to `dharmamitra.org/api/tagging/`; the live API now returns **422 Unprocessable Entity** (payload schema changed). All 6 `test_dharmamitra_engine.py` failures trace here. Two problems: (a) the live integration is broken against the current API; (b) tests hit the real network, so the suite fails offline / in CI.
**Fix:** (a) update the request payload to the current Dharmamitra schema (compare with `deep_read/dharmamitra_segmenter.py:87` which uses `{"texts":[...], "mode":"unsandhied", "human_readable_tags":True}`); (b) mock the HTTP call in tests, add one live smoke test marked `@pytest.mark.network`.

### H2. CORS wildcard + credentials
**`sanskrit_analyzer/api/app.py:31,63-69`** — GAP
`allow_origins=["*"]` with `allow_credentials=True` → Starlette reflects the caller Origin and sets `Access-Control-Allow-Credentials: true`; any site a logged-in user visits can make credentialed calls.
**Fix:** explicit origin allowlist when credentials are on, or `allow_credentials=False` for the wildcard dev default.

### H3. Streamlit call unguarded → raw traceback
**`sanskrit_analyzer/ui/app.py:60` + `ui/api_client.py:169`** — GAP
`handle_analyze` → `asyncio.run(client.analyze(...))` with no catch-all; the client only catches `httpx.*`. A 200 response with a non-JSON body (HTML error page) raises `JSONDecodeError` → full Streamlit traceback instead of `st.error`.
**Fix:** wrap `analyze` in a catch-all returning `APIError`; guard `asyncio.run` in `handle_analyze`.

### H4. Corpus cache `set()` wipes user disambiguation
**`sanskrit_analyzer/cache/sqlite_corpus.py:232-240`** — BUG
`INSERT OR REPLACE` omits `disambiguated` / `selected_parse` and resets `created_at`/`access_count`. After `update_disambiguation`, the next `set()` for that key silently deletes the user's choice.
**Fix:** `UPDATE ... ON CONFLICT` upsert that preserves those columns.

### H5. TieredCache SQLite read not guarded
**`sanskrit_analyzer/cache/tiered.py:174-177`** — GAP
Unlike the write paths, the SQLite read (`json.loads`/`datetime.fromisoformat`) has no try/except; a corrupt row crashes an ordinary analysis request instead of degrading to a cache miss.
**Fix:** wrap in try/except, count error, `return None`.

### H6. DeepRead fallback re-raises `VidyutUnavailable`
**`sanskrit_analyzer/deep_read/facade.py:118`** — GAP
The local-engine fallback calls `engine.analyze_word`, which re-raises `VidyutUnavailable` (`kosha_engine.py:418`); nothing catches it. With Dharmamitra unreachable **and** no vidyut bundle, `DeepRead().analyze()` crashes instead of degrading.
**Fix:** catch `VidyutUnavailable`, return an `unknown`-token result with a note.

### H7. LLM disambiguation result discarded
**`sanskrit_analyzer/disambiguation/pipeline.py:82`** — BUG
`disambiguate_single` returns `max(candidates, key=confidence)`, but the LLM stage reorders by semantic ranking *without* changing confidence values, so the LLM's top pick is dropped whenever it isn't also highest-confidence — the LLM stage is a no-op for selection.
**Fix:** when `resolved_at == LLM`, take `candidates[0]`; or have the LLM stage rewrite confidences.

## P2 — Medium

### Engines
- **`engines/ensemble.py:299-311`** BUG — `_calculate_lemma_agreement` returns `1.0` when only one engine contributed a segment, inflating `overall_confidence` toward 0.95 for single-engine segments.
- **`engines/ensemble.py:244-265`** BUG — `_merge_results` aligns engines by list index, not surface span; engines that split sandhi differently get compared as disagreements (`nara|siMha` vs `narasiMha`) and votes are dropped.
- **`engines/heritage_engine.py:96-141,210-219`** GAP — `_parse_heritage_response` is a stub: returns the whole input as one unsplit segment with confidence 0.5-0.7, polluting ensemble voting. Implement real HTML parse or mark engine unavailable.

### API / MCP
- **`api/routes/dhatu.py:116,140,163,199`** GAP — `async def` handlers run synchronous SQLite on the event loop; blocks all requests under concurrency. Use `run_in_threadpool`/`asyncio.to_thread`, reuse a shared handle.
- **`api/routes/analyze.py:272`** GAP — `body.engines` forwarded unvalidated; `{"engines":["bogus"]}` → unhandled 500. Validate against the known engine set, return 400.
- **`api/routes/analyze.py:267-276`** GAP — no try/except around `analyzer.analyze`; engine failure on valid text → bare 500 inconsistent with the module's `HTTPException` contract.
- **`mcp/tools/dhatu.py:204`** BUG — `if not 1 <= gana <= 10` runs before the `try`; a client sending `{"gana":"3"}` (string) raises uncaught `TypeError`. Coerce/validate inside the guarded block.

### Cache / deep_read
- **`cache/sqlite_corpus.py:81`, `data/dhatu_db.py:74`** GAP — connections opened with no `busy_timeout`/WAL → `database is locked` under concurrent access. Add `PRAGMA busy_timeout=5000; PRAGMA journal_mode=WAL;`.
- **`cache/sqlite_corpus.py:467-471`** GAP — `close()` only closes the calling thread's connection; other threads' handles leak for process lifetime.
- **`cache/sqlite_corpus.py:210-240`** GAP — SQLite corpus tier has no TTL/eviction/size cap; `corpus.db` grows unbounded.
- **`cache/tiered.py:288-304`** GAP — cache key `sha256("{mode}:{text}")` has no analyzer/model/schema version; stale results served indefinitely after an upgrade. Fold a version string into the key.
- **`deep_read/facade.py:251`** GAP — `_analyze_sloka_sync` uses `asyncio.run`, which raises inside a running loop; the analyzer path is silently unavailable in the async server context (caught at :218, returns `None`).
- **`deep_read/dharmamitra_segmenter.py:36`** GAP — `float(os.environ.get("DHARMAMITRA_TIMEOUT","30"))` at import; a bad value raises `ValueError` at import, taking down the whole package. Parse defensively.

### Training
- **`training/data_generator.py:148-158`** GAP — output never routed through `GrammarFormatConverter`; even after C3, `cmd_validate` flags every example ("Missing required field: sandhi_groups").
- **`training/reasoning_templates.py:187-192`** BUG — `detect_applicable_rule` always returns `"semantic_coherence"` with generic `"Parse N"` params; the other templates are dead, disambiguation reasoning is content-free.
- **`training/data_generator.py:113-125`** GAP — `--max-examples` limits *analyzed* entries, not *written* ones; writes far fewer than requested.
- **`training/corpus_loader.py:88-93`** GAP — `json.load` with no error handling; a malformed corpus file crashes with an uncaught `JSONDecodeError`.
- **`training/cli.py:223-224`** BUG — `stats` assumes numeric `confidence`; a `null` value → `TypeError` aborts the run; missing values averaged as 0.0 deflate the mean.

### UI
- **`ui/api_client.py:34`** BUG — non-dict confidence passes through as `None`; render sites do `int(confidence*100)` → `TypeError` crash (`results_header.py:53`, `parse_tree.py:75`, …). Coerce to float with default.
- **`ui/api_client.py:66-74`** GAP — transform drops `engine_votes`, `sandhi_type`, `is_compound`, `compound_type`; those parse-tree UI branches are permanently dead.
- **`ui/app.py:143`** BUG — `_handle_parse_select` mutates stored `parses` in place (`insert(0, pop(i))`), discarding the confidence ranking and desyncing the diff-view selectboxes. Track `selected_parse_id` instead.

### Embeddings / disambiguation
- **`disambiguation/rules.py:305,373`** BUG — `FrequencyPreferenceRule`/`SandhiPreferenceRule` mutate `candidate.confidence` in place on a shallow-copied list; repeated calls compound confidence → non-idempotent. `deepcopy` or return new instances.
- **`embeddings/training/projection_head.py:58`** GAP — `torch.load(path, weights_only=False)` full-pickle deserialization → arbitrary code execution on an untrusted `.pt`. Use `weights_only=True` + JSON config sidecar.

## Suggested Remediation Order

1. **C1, C2, C3** — verified criticals, each silently breaks a whole subsystem. Small, contained fixes.
2. **H1** — unbreak Dharmamitra + de-network the tests so the suite is green and CI-safe.
3. **H2** (CORS) and the input-validation GAPs (`analyze.py:272`, `dhatu.py:204`) — security surface.
4. **H4, H5, H6** — cache/deep_read correctness & resilience.
5. Batch the Medium items by subsystem (they cluster: ensemble alignment, SQLite hardening, training pipeline, UI transform).
6. Low items as cleanup; pin model revisions before the next embedding index rebuild.
